# 英会話学習アプリのエピック一覧

単語、リスニング、AI英会話をつなぎ、高校2年生程度の英語知識からビジネス会話まで学べるアプリを完成させるための開発単位です。[ロードマップ](roadmap.md) の順序で進めます。

2026年10月12日に EPIC-01 の要件確認に着手しました。EPIC-02〜09 は未着手です。EPIC番号はこのプロジェクト内の識別子で、外部サービスのIssue番号ではありません。機能の詳細と完了条件は提案であり、EPIC-01 の決定で更新します。28件のPBIをGitHubに登録し、各エピックのSub-issuesに関連付けています。番号の対応は pbis.json を参照してください。

## EPIC-01 学習目標と製品要件を決める

GitHub Issue：[1](https://github.com/shuichiro-hayafuji/bowmore/issues/1)

**状態：** 要件確認中。PBI-01.1（Issue #10）では、利用者を本人と友人の約5人、対応端末をiPhoneのみ、学習時間を1回10分と確認しました。最初の場面はユーザーから選定を任され、「自己紹介と仕事紹介」を採用しました。仕事での目標は会議で意見を述べることと提案することです。ChatGPTの契約枠を利用する希望と、難しい場合はBedrockを使う方針を記録しました。アカウント連携の制約と暫定費用はロードマップを参照してください。5人合計の月額上限7,000円と、録音を永続保存しない方針に合意しました。会話の文字と改善点を保存し、自分の履歴のみの閲覧と削除を可能にし、各自が削除するまで保存する方針に合意しました。本人と友人の開始状態は異なるとの申告を受け、学習設計案をロードマップに追加しました。完成版は会議での意見・提案を中心とし、専門的な商談・契約交渉・資格試験対策を対象外とすることに合意しました。PBI-01.1 の要件確認はチャットで完了し、PBI-01.2 の評価基準案を作成しました。誤りの訂正は会話後にまとめて行う方針に合意し、振り返りの設計案を追加しました。100パターンのメニューのうち、その人の難易度に合う候補からランダムに提案する方針に合意しました。20テーマ×5構成の案を作成し、開始状態に合わせた本人用・友人用の抽選を試作で確認しました。段階別評価基準、ランダム提案の追加ルール、頻度、履歴の保存場所・削除の実装方法、外部送信先の音声保持条件は未確定です。最新のユーザー回答によりApple Developer Programは登録済みとし、登録料は今回の予算から除外します。非掲載アプリ（Unlisted）方式でApp Storeから配布し、招待した人だけが利用できる方針に合意しました。開発チームの有効な権限と署名・審査・非掲載配布承認は未確認です。GitHubへの回答の反映は未実施で、EPIC-01 全体の完了条件は未達です。

**成果：** 誰が、どの環境で、何をできるようになるアプリかを決め、完成条件を共有します。

**依存：** なし。**優先度：** 最優先。

**対象範囲：** 個人利用／一般公開、対応環境、学習場面、開始レベル、学習時間の想定、運用予算、音声データの扱い、初期版の対象外。

**完了条件**

- [ ] 確定要件、提案、未決事項を分け、実装前に必要な事項を決定する。
- [ ] 「ビジネス会話」の対象場面と、場面ごとの用件達成の基準を定義する。
- [ ] リスニングとスピーキングの開始時・終了時の評価方法を定義する。
- [ ] MVPと完成版の範囲、対象端末、費用上限、音声の保存・削除方針を合意する。
- [ ] 開発体制と稼働時間を確認し、見積もりの前提を記録する。

**子Issue候補：** 要件Q&A／学習段階と評価基準／主要画面と学習導線／対象外と完成条件の整理。

## EPIC-02 音声AIの実現性を検証する

GitHub Issue：[2](https://github.com/shuichiro-hayafuji/bowmore/issues/2)

**成果：** 対象端末で、利用に耐える品質と費用の音声会話が成立することを確かめます。

**依存：** EPIC-01。**優先度：** 最優先。

**対象範囲：** 録音、音声認識、AI応答、音声再生、ターン制／リアルタイム方式の比較、待ち時間、費用、失敗時の動作。検証用の小さな試作品に限定します。

**完了条件**

- [ ] 評価前に、許容する待ち時間・品質・1回の学習費用と測定条件を定める。
- [ ] 日本語話者の英語、言い直し、無音、周囲の雑音を含む固定例で動作を確認する。
- [ ] マイク拒否、通信切断、応答失敗から中止・再試行できる。
- [ ] 音声の外部送信先と保存条件を確認し、秘密情報を端末に露出させない構成を選ぶ。
- [ ] 実測値、月額試算、制約、採用理由を記録し、基準を満たさない場合の縮小案を決める。

**子Issue候補：** 音声経路の試作／方式と提供元の比較／品質・遅延・費用の測定／採用判断。

**準備状況：** ユーザーがAWSアカウント435013325489のシドニーのコンソールURLを指定しました。ブラウザではサインイン画面までで、実際のAPI権限は未確認です。Nova 2 Sonicの公式対応表にシドニーは掲載されず、東京での音声検証を候補として整理しました。東京の利用は未合意です。EPIC-01は未完了で、音声検証本体には未着手です。

## EPIC-03 学習開始と履歴保存の基盤を作る

GitHub Issue：[3](https://github.com/shuichiro-hayafuji/bowmore/issues/3)

**成果：** 学習者が開始地点を選び、教材を使い、前回の続きから再開できます。

**依存：** EPIC-01、02。**優先度：** MVP必須。

**対象範囲：** 初回設定、簡易レベル確認、共通教材形式、学習セッション、履歴、保存と削除、基本画面。認証や端末間同期は利用範囲に応じて決定します。

**完了条件**

- [ ] 語彙・文法の知識と、聞き取り・発話の状態を区別して開始地点を設定できる。
- [ ] 診断をやり直す、または難易度を変更できる。
- [ ] 単語、音声教材、会話場面を同じ学習テーマに関連づけられる。
- [ ] 学習開始時に、その人の現在の難易度に合う候補からランダムなメニューを提案し、毎回の手動選択を必須にしない。候補は教材化・検証済みの範囲とする計画案で、100件の全教材が完成したとは扱わない。
- [ ] 学習結果が保存され、アプリを開き直して再開できる。
- [ ] 会話の文字と改善点を各自が削除するまで保持し、録音ファイルを永続保存しない。
- [ ] データの保存方針に沿った削除ができ、複数利用者の場合は他人の履歴にアクセスできない。

**子Issue候補：** 初回設定とレベル確認／教材・履歴のデータ設計／保存・再開／データ削除とアクセス制御。

**音声の扱い：** 録音ファイルは永続保存しません。EPIC-04、05 の自分の録音を聞き直す機能は未合意の提案として見直します。一時的な録音・再生を採用するかは別途決定し、採用する場合もセッション終了後に残さない設計にします。会話の文字と改善点は保存し、各自が自分の履歴だけを閲覧・削除できる方針です。保存期間は各自が削除するまでとします。保存場所と削除の実装方法は別途決めます。

## EPIC-06 AIと音声で会話する

GitHub Issue：[6](https://github.com/shuichiro-hayafuji/bowmore/issues/6)

**成果：** 学習レベルに合うAI相手と、自分の声でやり取りし、改善点を確認できます。

**依存：** EPIC-02、03。EPIC-04、05 の同一テーマ教材と結合してMVPを完成させます。**優先度：** MVP必須。

**対象範囲：** 場面選択、AIの役割と会話目標、音声入力・応答、聞き返し、ヒント、難易度、終了後の振り返り。自由会話の拡張はMVPの必須条件にしません。

**完了条件**

- [ ] 学習者が音声で話し、AIの音声応答を受けて複数ターンの会話を続けられる。
- [ ] AIが設定した場面とレベルに沿って応答し、会話終了まで用件を維持する。
- [ ] 聞き返し、ヒント、認識結果の確認、再録音、中断・再試行ができる。
- [ ] 終了後に、できたこと、改善点、より自然な表現を発話例とともに確認できる。
- [ ] 音声認識の不確実性を扱い、認識された文字だけで発音の正しさを断定しない。
- [ ] 固定の会話例で、許容表現への過剰な訂正や不適切な難易度がないか評価する。
- [ ] 単語→リスニング→AI会話→結果保存を一つのテーマで通して確認する。

**子Issue候補：** 場面別会話設計／音声会話画面／ヒントと復旧／フィードバック評価／MVP通し検証。

**訂正のタイミング：** 会話後にまとめて改善点を示します。会話中は文法や表現の訂正で中断せず、聞き返しや求められたヒントによって会話を支援する案です。終了後の改善点は実際の発話と対応づけ、認識が不確かな箇所を断定しないことを検証します。

**成果：** 苦手な内容を繰り返し学び、聞く力と話す力の変化を確認できます。

**依存：** EPIC-04、05、06。**優先度：** 完成版必須。

**対象範囲：** 復習候補、復習時期、次の学習の提案、履歴、段階別の確認課題、難易度の調整。初期のランダムなメニュー提案はEPIC-03で扱う計画案とし、苦手な内容に応じた重み付けをここで検討します。

**完了条件**

- [ ] 間違えた語句、聞き取れなかった表現、会話の改善点を復習に戻せる。
- [ ] 学習結果と経過時間を基に、復習する内容を選べる。
- [ ] なぜその復習を勧めるか分かり、学習者が内容や難易度を変更できる。
- [ ] 開始時と同程度の別課題を使い、聞き取りと会話を別々に比較できる。
- [ ] 同じ入力に対するAI評価のばらつきを確認し、人の評価例との不一致を点検する。
- [ ] 利用日数と能力評価を分け、不確かな結果でレベルを自動確定しない。

**子Issue候補：** 復習ルール／次の学習の提案／進捗画面／比較課題と評価の検証。
